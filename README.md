# webtyp/indexdb
<img src="docs/img/badges.svg">
**Run SQL-style queries in the browser — the same Go ORM code, zero changes.**

`webtyp/indexdb` is an [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) driver for [`webtyp/orm`](https://github.com/webtyp/orm), compiled to WebAssembly with Go. It lets you use a familiar `Create`, `Query`, `ReadOne`, `ReadAll` API directly in the browser, backed by the browser's built-in persistent storage engine — no server, no SQLite file, no extra runtime.

**Why this matters:** your data-access logic stays the same whether it runs on a server (with a SQL backend) or in the browser (with IndexedDB). Swap the driver, keep the code.

## Initialization & Schema Upgrade

```go
// New opens (creating or upgrading as needed) the IndexedDB database name and makes sure an
// object store exists for every model. Missing stores are created by reopening the database
// with version+1; existing stores and their data are never dropped.
func New(name string, models ...model.Model) (storage.Conn, error)
```

Schema upgrades are additive and automatic. The library reconciles the IndexedDB database by opening it and checking if any object stores (declared via the models passed to `New`) are missing. If so, it will automatically bump the database version and create the missing object stores. It will never drop any existing store, meaning existing user data stays safe even if a model is removed.

If an old version of the app is open in another tab, the upgrade might be blocked. In this case, `New` returns an error: `indexdb: upgrade blocked by another open tab of this app; close it and reload`.

### Full Example

```go
package main

import (
	. "webtyp.com/fmt"
	"webtyp.com/indexdb"
	"webtyp.com/orm"
	"webtyp.com/model"
)

// ModelName, Schema and Pointers are auto-generated by ormc — you only write the struct.
// See: https://github.com/webtyp/orm
type User struct {
	ID    string
	Name  string
	Email string
}

func (u *User) ModelName() string { return "users" }
func (u *User) Schema() []model.Field {
	return []model.Field{
		{Name: "ID", Type: model.Text(), DB: &model.FieldDB{PK: true}},
		{Name: "Name", Type: model.Text()},
		{Name: "Email", Type: model.Text(), DB: &model.FieldDB{Unique: true}},
	}
}
func (u *User) Pointers() []any { return []any{&u.ID, &u.Name, &u.Email} }
func (u *User) Values() []any { return []any{u.ID, u.Name, u.Email} }
func (u *User) EncodeFields(wr model.FieldWriter) {}
func (u *User) DecodeFields(r model.FieldReader) {}
func (u *User) IsNil() bool { return u == nil }

func main() {
	// 1. Initialize the database
	conn, err := indexdb.New("my_app_db", &User{})
	if err != nil {
		Println("db open error:", err)
		return
	}
	db := orm.New(conn)

	// 2. Create a record
	user := User{ID: "1", Name: "John Doe", Email: "john@example.com"}
	err = db.Create(&user)

	// 3. Query a record
	var result User
	err = db.Query(&result).Where("ID").Eq("1").ReadOne()
}
```

## Migration from old API

| I want X | use Y |
| --- | --- |
| Create a new IndexedDB instance | `conn, err := indexdb.New("db_name", &ModelA{}, &ModelB{})` |
| Get a logger for IndexedDB | (Removed) Errors are now directly returned from `New` or queries. |
| Inject an IDGenerator | (Removed) ID generation belongs to the caller logic, not the storage driver. |
| Add a new Model/Table | Add it to the models passed to `New`; the missing store will be created automatically. |
